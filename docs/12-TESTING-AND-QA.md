# 12 - Testing and Quality Assurance

## Tooling and isolation

[composer.json](../composer.json) declares PHPUnit ^9.5.10, Mockery and Faker. Node's built-in runner executes four `tests/JavaScript/*Test.cjs` files. [phpunit.xml](../phpunit.xml) defines Unit and Feature suites and forces APP_ENV=testing, SQLite :memory:, empty DATABASE_URL, array cache/mail/session and sync default queue. [CreatesApplication](../tests/CreatesApplication.php) invokes [IsolatedDatabase](../tests/Support/IsolatedDatabase.php), which asserts isolation, fakes public/private/local storage, blocks outgoing HTTP through OfflineHttpFactory and migrates/seeds only that empty connection.

PHP test storage fakes, logs and cache output still write test/runtime artifacts. They were not run for this documentation-only task. Do not interpret the existence of tests as proof they currently pass.

## Commands

Run from an approved development/test checkout after satisfying dependencies:

```powershell
php vendor/bin/phpunit --testsuite=Unit
php vendor/bin/phpunit --testsuite=Feature
php vendor/bin/phpunit --filter=TicketReassignmentTest
node --test tests/JavaScript/HrChatCoreTest.cjs tests/JavaScript/MediumSecurityTest.cjs tests/JavaScript/SkillTagsTest.cjs tests/JavaScript/SurveyPwaTest.cjs
node tests/Support/production-build-check.cjs
```

The build helper uses temporary output and verifies app.js/app.css, then removes its own temporary directory. It was inspected, not executed here. Production build command in package.json is npm.cmd run production; that normally writes published assets and must not be run casually in a docs-only working tree.

## Engine and browser probes

[phpunit.engine.xml](../phpunit.engine.xml) selects tests/Engine. Its ordinary isolated harness requires explicit ENGINE_TEST_DRIVER/HOST/PORT/DATABASE/USERNAME/PASSWORD/CONFIRM and optional TRUST_CERTIFICATE. The database must be separately named `ec_engine_test_<8-32 lowercase letters/digits>`, empty and confirmed, with protected application names rejected and actual identity checked before migration. These tests can create schema/data in that approved isolated database.

**Do not run the engine configuration as a blanket command without selecting the intended probe and authorization.** tests/Engine also contains [AuthorizedEngineDataTest](../tests/Engine/AuthorizedEngineDataTest.php) and [AuthorizedEngineDatabase](../tests/Support/AuthorizedEngineDatabase.php), an explicitly gated harness for a particular existing database that can write fixture records. Its presence is not authorization to reuse that target. This task did not set its confirmation flag or execute it.

Browser fixture/server helpers exist in tests/Support for chat rendering and signed interaction; their existence does not prove a browser session passed. No browser automation, real PDF/OCR samples, AI request, SMTP delivery, engine migration or live HTTP smoke test was executed here.

## Recommended manual acceptance cases

Use synthetic fixtures, each role separately and an isolated copy of the configured database engine. These cases are recommendations, not executed results.

| Area | Normal | Invalid / boundary / denied / failure |
| --- | --- | --- |
