# HR Assistant review and provider switching

Anthropic remains the active dependency in `HrChatController`. PHP 7.4, Laravel 8, Backpack, package versions and lockfiles are unchanged. Tests use guarded SQLite `:memory:`, fake storage and offline/mocked HTTP. No live database migration, data update, attachment cleanup, deployment or paid provider request was performed.

## Confirmed problems fixed

- Provider errors previously became successful, cited answers and persisted conversation memory. Both services now throw a safe `PolicyChatException`; the controller returns 503 without saving an answer or sources. Missing credentials, transport failures, HTTP errors, malformed/empty responses, refusals and truncated completions fail safely. Logs retain numeric token counts, HTTP status and exception class only, without provider bodies, questions or transport messages. Neither service retries automatically or calls the other provider.
- Gemini previously ignored history, put instructions into the question, exposed its key in the URL, and permitted training-knowledge answers. It now implements `ask(string $question, string $policyContext, array $history = []): string`, maps assistant history to `model`, sends a separate `systemInstruction`, authenticates with `x-goog-api-key`, and joins final text parts while excluding thought summaries. The existing `gemini-3-flash-preview` default is retained and configurable. Generation uses the model's default temperature rather than the old 0.2 override.
- Both providers share policy-only, bilingual instructions and defensive normalization: current question 600 characters, three complete history exchanges, history questions 600 characters and answers 6,000 characters, policy context 11,000 characters, output budget 4,096 tokens. Requests have a 10-second connection timeout and 60-second total timeout. Incomplete completions produce a recoverable failure, not a partial policy answer.
- Suggestions previously exposed other users' questions. Suggestions, transcripts, memory and feedback are scoped to their owner; inactive and unauthenticated users remain blocked by existing middleware. Clearing includes legacy logs without a conversation and deletes atomically. Persisting an answer rechecks the owned conversation under a short transaction so a deleted conversation is not resurrected.
- Retrieval previously appended old questions even on explicit topic changes, stripped Unicode and joined hyphenated words. It now expands only subject-free follow-ups using a small procedural-word heuristic, preserves Unicode word boundaries, bounds keyword/query size and orders ties deterministically. Only active documents are retrieved. Whole chunks are selected within the prompt budget so displayed sources correspond to supplied context. Retrieval failures no longer pretend that no policy was found.
- Markdown HTML escaping did not block unsafe link schemes. The renderer now also filters generated DOM to formatting tags and HTTP/HTTPS/mailto links; event attributes, executable markup and remote images are removed. Questions, titles and source labels remain literal text, and feedback identifiers must be positive safe integers.
- HTTP error bodies were rendered as successful answers, feedback showed thanks without verifying success, and old pending responses/transcripts could overwrite a newly selected chat. HTTP status handling, bounded browser requests, view-version guards and transport cancellation fix these cases. New/cleared chats detach their conversation identity. Clear-view cancels pending display updates while retaining the conversation. Duplicate sidebar refreshes were removed. Failed mutations report failure. Copy fallback restores focus and reports failure instead of claiming success.
- Widget drafts were shared across accounts. Keys now include the current account ID and old unscoped drafts are discarded. History restoration remains retryable, new-chat cancels stale restoration, closing restores launcher focus, and Escape works within the panel without delayed focus stealing.
- Policy activation trusted a stale route-bound status and could race with replacement/re-ingestion. It now rechecks the row under the ingestion lock. Successful re-ingestion preserves inactive policies; pending dispatch failures remain visible in list notes. OCR polling now enforces Symfony's per-page timeout and stops remaining subprocesses on failure. Failed PDF conversions cannot use partial output; zero-padded Poppler page numbers are recognized. Incomplete or unscored OCR is held in `needs_review`, outside chatbot retrieval.

## Remaining limits and operational work

Retrieval remains a bounded keyword heuristic, not semantic search; ambiguous follow-ups can still select irrelevant policies. Prompts and quoted document data reduce instruction confusion but do not guarantee factual grounding or prevent all prompt injection. Source pills identify supplied documents, not proof of every generated claim. Historical citations still resolve existing chunk IDs; replacing/deleting chunks can remove old source pills, and later title edits can change their labels. Very long transcripts still load the complete owned conversation.

All database checks in this review used SQLite `:memory:`. SQL Server/MySQL behavior, real Poppler/Tesseract PDF extraction and deployed authentication/session/rewrite behavior require a suitable isolated staging environment. The OCR process timeout test uses a PHP child, not installed OCR binaries. Live provider smoke checks need explicit paid-call authorization; deployment, environment/cache changes, queue migration rehearsal/application and worker supervision remain operational steps requiring authorization. No attachment reconciliation cleanup or previous deployment follow-up was performed or marked complete here.
